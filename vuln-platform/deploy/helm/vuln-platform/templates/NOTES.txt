Vulnerability Management Platform deployed.

1. Check rollout status:
   kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "vuln-platform.fullname" . }}

2. Check the migration Job succeeded (it runs as a pre-install/pre-upgrade hook):
   kubectl -n {{ .Release.Namespace }} logs job/{{ include "vuln-platform.fullname" . }}-migrate-{{ .Release.Revision }}

3. {{- if .Values.ingress.enabled }}
   The API should be reachable at:
   {{- range .Values.ingress.hosts }}
   https://{{ .host }}
   {{- end }}
   {{- else }}
   Ingress is disabled. Port-forward to reach the API locally:
   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "vuln-platform.fullname" . }} 8080:{{ .Values.service.port }}
   {{- end }}

4. If this is a first install and you set secrets.seedAdmin.* in your
   values, an administrator account was seeded on first boot. Log in
   and change that password immediately — see README.md's "Local
   setup" section for the login request shape.

5. IMPORTANT — this application talks to your production RHEL fleet
   over SSH and holds encrypted credentials for it. Before pointing
   this at real infrastructure, confirm:
   - networkPolicy.sshEgressCIDR matches your actual managed-fleet
     ranges (default value is a placeholder)
   - secrets.credentialEncryptionKey is a real, securely-generated
     32-byte value, not left as a placeholder
   - config.safety.allowFullSystemUpdate is false unless you've
     specifically decided otherwise
